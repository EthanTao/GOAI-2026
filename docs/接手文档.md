## 一、项目概述

**GOAI 2026 通用双臂协同操作挑战赛**（GOAI 2026 General Dual-Arm Collaborative Operation Challenge）。

第一阶段目标（也是当前唯一目标）：**跑通官方 baseline**，即用官方提供的环境与官方 checkpoint，在 12 个 generalization 任务（24 个配置，含 `_random` 变体）上跑本地 smoke test，并验证每个任务写出的 `eval_result/.../_result.json` 里 `eval_time >= 1`。

技术栈链路：**RoboDojo**（仿真环境，基于 Isaac Sim / IsaacLab）→ **XPolicyLab**（策略服务器，RoboDojo 的子模块）→ **ACT**（Action Chunk Transformer，官方模仿学习 baseline 策略）。

### 必须遵守的硬约束（来自主任务文档）

1. **禁止修改官方 benchmark 代码**：task 定义、评估逻辑、reward/打分、randomization、configurations 都不能动。
2. **第一阶段禁止设计新模型**：只用官方 ACT baseline。
3. **不要用** `scripts/init_assets.sh` 和 `scripts/RoboDojo/download_data.sh`——应使用 **GOAI-2026 数据集**。
4. **不要盲目改依赖**。
5. **每次修改都要可回滚**（用 git）。

## 五、关键发现与坑（★ 最重要，务必先读）

### 坑 1：磁盘空间严重不足（★ 最高风险）

- 系统盘 `/` 只剩 **32G**，数据盘 `/mnt/data` 只剩 **134G**。
- 但完整数据需求：Assets **35G** + data **240G** + checkpoint **34G** ≈ **309G**，远超 `/mnt/data` 的 134G。
- **结论**：`data`（240G 训练数据）当前放不下。smoke test 用官方 checkpoint 做**评估**，很可能**不需要**完整 240G 的 data。接手后需先确认 smoke test 到底需要多少 data，避免盲目下载撑爆磁盘。
- 任何大文件下载前，先 `df -h /mnt/data` 确认剩余空间。

### 坑 2：官方 checkpoint 命名与 ACT 代码不匹配（★ 必改）

- 官方 checkpoint 实际结构（已确认下载内容）：
  ```
  ckpt/RoboDojo/ACT/act-RoboDojo-<task>/arx_x5-100-joint/
      policy_epoch_6000_seed_0.ckpt
      policy_epoch_6000_seed_1.ckpt
      policy_epoch_6000_seed_2.ckpt
  ```
  每个任务 3 个 seed，约 40+ 个任务。
- 但 ACT 推理代码 `XPolicyLab/policy/ACT/detr/act_policy.py`（第 138-153 行）只认 **`policy_last.ckpt`**：
  ```python
  ckpt_path = os.path.join(ckpt_dir, "policy_last.ckpt")
  if not os.path.isfile(ckpt_path):
      raise FileNotFoundError(f"ACT policy checkpoint not found: {ckpt_path}")
  ```
- **待办**：需要为每个任务创建一个符号链接 `policy_last.ckpt -> policy_epoch_6000_seed_0.ckpt`（先确认用哪个 seed，默认 seed_0）。

### 坑 3：git "dubious ownership"（已解决，记录原因）

- `/mnt/data` 目录 owner 是 **root**，而用户是 `ethantao`，git 会报 `fatal: detected dubious ownership in repository`，导致 checkpoint 下载脚本误报 "Checkpoint root not found"。
- 已通过 `git config --global --add safe.directory '/mnt/data/*'` 解决。
- 以后在 `/mnt/data` 下跑 git 操作若再报 ownership，记得是同一个原因。

### 坑 4：HuggingFace 429 限流

- 直连 HuggingFace 下大文件会触发 `429 Too Many Requests`（IP 被限流）。
- 已改用 **ModelScope** 下 Assets（数据盘），checkpoint 走 **git LFS** 时相对稳定。
- 若 ModelScope 也慢，可考虑加 `HF_ENDPOINT=https://hf-mirror.com` 镜像。

### 坑 5：per-task checkpoint 与 smoke test 统一 `--ckpt` 的矛盾（★ 待解决）

- 官方 checkpoint 是**按任务分开**的（`act-RoboDojo-<task>`），每个任务一个目录。
- 但 `robodojo.sh smoke --ckpt <名字>` 对所有任务用**同一个** ckpt 名字，官方文档也没有 per-task 映射机制。
- **待办（需探索）**：确定 smoke test 如何为不同任务选不同 checkpoint。方向：
  1. 看 `scripts/robodojo.sh smoke` 和 `scripts/internal/run_policy_eval.sh` 是否有按 task 名拼 ckpt 名的逻辑；
  2. 或逐个任务单独 `eval --task <task> --ckpt act-RoboDojo-<task>` 跑；
  3. 或把 12 个 generalization 任务的 ckpt 各自符号链接成统一名字。

### 坑 6：策略环境与评估环境必须隔离

- 评估环境（RoboDojo）用 torch **2.7.0 cu128**。
- ACT 策略环境用 torch **2.4.1**（见 `XPolicyLab/policy/ACT/install.sh`）。
- 两个环境 **conda 隔离**，不要混装，否则 torch/CUDA 版本冲突。

### 坑 7：smoke test 的"成功"标准

- 每个任务退出码为 0 **不够**，还必须写出 `_result.json` 且其中 **`eval_time >= 1`**（见 `RoboDojo/CLAUDE.md`）。
- 所以验收时看 `eval_result/` 目录，别只看退出码。

## 六、关键命令速查

```bash
# 环境
conda activate RoboDojo

# doctor 检查（环境/资产/配置）
bash scripts/robodojo.sh doctor --skip-isaac --skip-conda --skip-policy

# smoke 测试（24 个配置，EVAL_NUM=1 默认）
bash scripts/robodojo.sh smoke --policy-dir XPolicyLab/policy/ACT --ckpt <CKPT> --policy-env <ENV> --dimension generalization

# 单任务 dry-run（不跑 Isaac/策略，只验证流程）
bash scripts/robodojo.sh eval --policy-dir XPolicyLab/policy/ACT --task stack_bowls --ckpt <CKPT> --policy-env <ENV> --dry-run

# 单任务真跑
bash scripts/robodojo.sh eval --policy-dir XPolicyLab/policy/ACT --task stack_bowls --ckpt <CKPT> --policy-env <ENV> --eval-num 1

# 列出可运行任务
bash scripts/robodojo.sh tasks

# 下载官方 checkpoint（已完成大半）
bash scripts/RoboDojo/download_ckpt.sh huggingface ACT

# 汇总 eval_result 成 markdown
bash scripts/robodojo.sh summarize
```

> 注意：policy 相关的 `setup_eval_*` 脚本必须在 **policy 目录** 下执行（CWD 是 policy 目录）。
