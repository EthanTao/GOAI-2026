## 一、项目概述

**GOAI 2026 通用双臂协同操作挑战赛**（初赛评测 RoboDojo **Generalization**：12 任务 × standard / `_random` = 24 配置）。

**当前唯一提交目标**：用 **RoboDojo 官方 Xiaomi-Robotics-1 微调 checkpoint** 做纯推理，跑通 24 配置本地 smoke（`eval_time >= 1`），部署公网 Policy Server，完成一次有效成绩提交。

```text
ckpt/RoboDojo/Xiaomi_Robotics_1/RoboDojo-sim-arx_x5-ee-0/
```

数据集：HuggingFace `RoboDojo-Benchmark/RoboDojo`。XPolicyLab 适配：`policy/Xiaomi_Robotics_1`。动作：**仅 `ee`**。

技术栈：**RoboDojo**（Isaac Sim / IsaacLab）→ **XPolicyLab**（Policy Server）→ **Xiaomi_Robotics_1**（官方已微调 VLA，不是 ACT）。

### 权威来源

1. **赛规**：https://xsparkai.com/goai-2026/ 、https://www.goaihz.com/tracks?track=embodied 、参赛手册 PDF
2. **本轮执行**：本文 + `docs/xiaomi_ops.md` + 08-14 design/plan
3. 根目录 `GOAI 2026 通用双臂协同操作挑战赛.md` 是 **Agent 任务书**，不是组委会赛规。「第一阶段只用 ACT / 每次只改一个因素」**作废**。

官方允许 XPolicyLab 里的 baseline 或自有模型。禁止改的是任务定义、评估、reward、randomization。正式评测中途不换模型 / action / 协议。每队 3 次有效成绩，取最高。

### 必须遵守的硬约束

1. **禁止修改官方 benchmark 代码**（task / eval / reward / randomization / configurations）。
2. **本轮不自己训练或微调**；只用官方 `Xiaomi_Robotics_1` RoboDojo ckpt。不用 Xiaomi-0、不用未微调的 5B、ACT 不作提交备用。
3. **不要用** `scripts/init_assets.sh` 和 `scripts/RoboDojo/download_data.sh` 拉全量训练数据——Assets 用 **GOAI-2026**；ckpt 用 RoboDojo 数据集里 **仅** `ckpt/RoboDojo/Xiaomi_Robotics_1/*`。
4. **不要盲目改依赖**；评估环境 `RoboDojo` 与策略环境 `mibot` 隔离。
5. **每次代码/文档修改都要可回滚**（git）。大文件不进 git。

## 五、关键发现与坑

### 坑 1：磁盘（本云机：只有 vda1）

- 没有 `/mnt/data`。大文件默认 `/home/ubuntu/GOAI-2026/`。
- **本轮不要** 240G `data/hdf5`，**不要**再下 34G ACT。
- 加 **10G** 云盘不够放 Assets（~35G），只够缓存；Assets 要 **50G+**。
- 任何大下载前 `df -h /`。剩余 < 20G 时不要开始下 Assets。

### 坑 2 / 坑 5：ACT ckpt 命名与 per-task 映射（已冻结）

这两条只针对官方 ACT（`policy_last.ckpt`、`act-RoboDojo-<task>`）。**本轮不走 ACT。** Xiaomi-1 是一份 `RoboDojo-sim-arx_x5-ee-0`，`--ckpt Xiaomi_Robotics_1` 即可。若 `robodojo.sh` 拼接路径与 policy 约定不一致，用 `eval.sh` 按任务跑，结论补记本节。

### 坑 3：git "dubious ownership"（笔记本历史）

笔记本 `/mnt/data` owner 曾是 root。本云机不涉及。

### 坑 4：HuggingFace 429（仍有效）

直连 HF 易 429，HF 镜像还会跳海外 CDN。**ckpt 与 Assets 都优先魔搭**（`modelscope.cn`）。

### 坑 6：策略环境与评估环境必须隔离（仍有效，版本已变）

- 评估：`RoboDojo`，torch **2.7.0** cu128。
- 策略：`mibot`，torch **2.8.0** cu128（不再是 ACT 的 2.4.1）。
- 禁止混装。

### 坑 7：smoke 成功标准（仍有效）

退出码 0 不够，必须 `_result.json` 且 **`eval_time >= 1`**。

### 坑 8：显存与驱动（本云机）

4090 24GB 够跑 Xiaomi-1 推理。与 Isaac 同卡时一次一个环境。  
**驱动**：官方 RoboDojo 要求 **570/580**；本机曾是 **525.105.17**（CUDA 12.0）。不升级则 Isaac Sim 5.1 / torch cu128 会失败。

### 坑 9：action_type 只能 ee（本轮新）

`Xiaomi_Robotics_1` 拒绝 `joint`。提交字段必须 `ee`，评测期间不改。

## 六、关键命令速查

完整说明见 `docs/xiaomi_ops.md`。

```bash
df -h /

# 策略环境（仓库在 RoboDojo/ 内）
cd /home/ubuntu/GOAI-2026/RoboDojo/XPolicyLab/policy/Xiaomi_Robotics_1
bash install.sh
conda activate mibot

# 官方 XR-1 ckpt（不要 download_ckpt.sh ACT）
hf download RoboDojo-Benchmark/RoboDojo \
  --repo-type dataset \
  --include "ckpt/RoboDojo/Xiaomi_Robotics_1/*" \
  --local-dir /home/ubuntu/GOAI-2026/checkpoints/Xiaomi_Robotics_1 \
  --local-dir-use-symlinks False

# debug
cd /home/ubuntu/GOAI-2026/RoboDojo/XPolicyLab/policy/Xiaomi_Robotics_1
EVAL_ENV_TYPE=debug bash eval.sh RoboDojo stack_bowls Xiaomi_Robotics_1 arx_x5 ee 0 0 0 mibot RoboDojo

# doctor / smoke（在含 scripts/robodojo.sh 的目录）
conda activate RoboDojo
bash scripts/robodojo.sh doctor
bash scripts/robodojo.sh smoke \
  --dimension generalization \
  --policy-dir XPolicyLab/policy/Xiaomi_Robotics_1 \
  --ckpt Xiaomi_Robotics_1 \
  --policy-env mibot \
  --eval-env RoboDojo \
  --action-type ee \
  --eval-num 1

bash scripts/robodojo.sh summarize
```

policy 的 `eval.sh` / `setup_eval_*` 必须在 **policy 目录** 下执行。
